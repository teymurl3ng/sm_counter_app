# B1a profile receiver — complete at the bounded QA scope

The receiving engine now applies complete Product, Customer, Vendor, Salary/Employee and Operating Expense/category profile satellites on both new and existing parent UIDs. It resolves the child's key from the receiving database, so sender-local numeric IDs are ignored. Optional fields can be cleared; rates, limits, active/archive flags, and expense display names update. Parent and child are in one record savepoint. A missing `profile` key preserves a legacy local satellite; explicit null, incomplete or invalid profile data refuses the record without changing its parent. The existing pending-local-edit guard still parks incoming parent rows, and pulled profile writes do not enqueue an echo.

The isolated QA APKs built successfully. On S24, the [two focused receiver tests](b1a-profile-receiver-s24.log) passed 2/2, covering five-family create/update/replay with different local IDs, catalog/category reads, legacy missing-profile preservation, malformed rollback and pending-local-edit protection. The [three affected capture/apply regressions](b1a-affected-regression-s24.log) passed 3/3. One old outbox test had asserted that an already queued parent moves to the tail; the implementation deliberately preserves its queue position. The test now checks that position and that a later profile edit enqueues the parent after the earlier entry is cleared.

This result closes receiver behavior only. The subsequent [B1b result](B1B_RESULT.md) completes controlled catch-up at the bounded QA scope. No ordinary app, live shop data, server RPC, enrollment, pull cursor, commit or push was changed by B1a.
