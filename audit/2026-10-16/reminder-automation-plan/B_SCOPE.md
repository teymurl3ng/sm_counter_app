Acquire/start/digest/review/snooze/resolve commands compare those heads before changing state; Android B must first drain/pull through its existing sync gate, reject required held/pending work, read consistent local facts and supply those heads. The server does not calculate balances or certify unuploaded offline payments. Missing/invalid shop timezone refuses activation/scheduling rather than guessing. Preferred notification time must be outside quiet hours; otherwise a same-day preferred-time gate could defer forever. Android B must expose that validation before save.

Two version layers: policy/customer CAS revision changes on every accepted edit; schedule revision/effective date changes only when cadence or enable activation changes. Quiet-hour/primary/pause/snooze edits must not create a new statement cycle. A receives schedule revisions in its existing cycle model. Shop schedule remains weekly; customer overrides weekly/monthly/anchored 1–365 day interval or inherited. Pause preserves cadence; snooze is a separate date, never a sale term edit.

Claim protocol: ACQUIRE grants a five-minute preparation attempt, RENEW extends a still-owned live preparation, RELEASE only releases preparation. Expired preparation may be replaced. START requires a fresh snapshot and the same active actor/install/attempt; it durably becomes HANDOFF_STARTED with no automatic expiry. Original successful START alone returns launch_authorized=true. Any replay returns replayed=true and launch_authorized=false, even for a lost response. Original DIGEST alone can return notify_authorized=true; any replay or second daily reservation returns false. This prefers a missed handoff/alert over a repeated side effect.

REVIEW/SNOOZE cannot silently clear another active preparation or any started handoff. RESOLVE targets the exact attempt with explicit uncertainty acknowledgment and operator-reported outcome; own leadership actor/install may resolve its own attempt, Owner may resolve another installation. REVIEWED acknowledges the claim's cycle/current server business date; REPORTED_NOT_OPENED and RETRY_UNCERTAIN clear only that claim, never pretend delivery or payment. A competing started handoff blocks disabling coordination; pausing/changing settings cannot erase uncertainty. App wiring must not automatically resolve merely because it resumes.

Owner policy can assign this current installation as primary; no offline election. Digest validates primary actor/install, current server shop date, preferred time/quiet hours, fresh heads and positive client-calculated eligible work. One reservation/shop/day survives transfer and settings edits. Background Android must honor permission/channel denial before requesting a reservation and keep in-app attention. No customer detail is stored in the digest.
