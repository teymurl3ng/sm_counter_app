Do not route unfinished controls into the ordinary app. No scheduler, notification/channel, external composer launch, cloud/schema mutation, phone release install, provider work or deferred wording sweep in this checkpoint.

Two Room tables, additive DB18→19 migration, exported schema19. Cache is one accepted metadata-only snapshot per environment/server/shop/server-staff/installation binding; no copied balance or contact information. It supports display, never financial freshness or action authorization. Rejected/malformed/failed refresh cannot make a cache current; revoked access drops it. Snapshot checks exact version/types, shop, dates, revisions, duplicate identities, claim phases and sorted action heads. Map schedule revisions (not edit revisions) into A's existing calculator.

Journal records the exact UUID/body and original binding before any request. HTTP/network cancellation/unknown/malformed acknowledgment keeps the request for explicit review/recovery. Never automatically drain reminder commands during ordinary sync. Exact retries retain the original ID/body; a changed body/binding is refused. A recovered/restored/already-journaled START/DIGEST can never grant a side effect, even if the server accepts it as a previously unseen request. Original validated success is durably removed before a live in-memory grant is returned; replay/malformed/unmatched responses grant nothing. No grant is serialized in Room or backup. Consumer-side fresh financial gating and actual external actions remain the existing next B wiring.

Use existing redacted SyncHttp/token storage and the process-wide SyncOperationGate; one 401 refresh retry, unknown refresh preserves tokens. Read-only runtime loading requires a current local full-financial Owner/Admin/Manager session plus enrolled server binding, then the actual server checks its current actor. No fabricated local session or background Owner password. Ordinary drain/pull behavior stays unchanged until the selected scheduling/UI wiring is ready.

Encrypted backup schema13→14 (distinct from Room version). Export unfinished command journal only; omit derived cache. Business restore clears old cache/journal transactionally, validates recovered requests, and marks every imported row recovery-only. Schema13 and older have no reminder section; reject attempts to hide new journal rows under an older schema. Older app readers reject schema14. Binding/install mismatch never silently adopts a restored request.
