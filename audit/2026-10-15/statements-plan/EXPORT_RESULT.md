# Phase 5, piece 2: measured statements and Android sharing

16 October 2026. Baseline `842a1e1`. ✅ ~~PDF/image export and Android sharing.~~ Phase 5 still has piece 3, manual message review/composition and truthful local action history. No new phase or whole-app audit was added.

One measured A4 layout now supplies the on-screen page image, PDF and numbered PNGs from the same immutable statement. It replaces piece 1's provisional eight-row grouping. The bundled Manrope faces, existing forest/ink/supporting/amount colors, neutral product markers and current catalog names provide the hierarchy. Text wraps; ordinary entries stay together; unusual entries continue with their reference; headers, carried balances and page numbers repeat. A native scalable text equivalent of each page remains available through Read statement text. The shared app header/footer are unchanged.

Share statement opens the planned PDF/Images choice dialog and then Android's chooser. It shows preparation, cancellation and actionable failures, guards duplicate work, and checks current customer/period/authorized facts both before rendering and immediately before handoff. Changed facts require refreshed review. Opening or dismissing the chooser never claims a message was sent. No real recipient or sending action was selected in QA.

Generated files live only in an opaque UUID subdirectory of private cache. The dedicated, non-exported FileProvider exposes only that export subtree, grants read access to selected content URIs, and requests no storage or SMS permission. Active preparations retain a lease; cancellation/failure removes their partial output, including cancellation while a completed export is being returned from IO. Successfully handed-off files remain available until Android evicts them or the next app-start/statement-use cleanup finds them at least 24 hours old. Cleanup excludes active leases and unrelated directories. A 64 MiB cache budget, 40-page limit, bounded image size and explicit oversized-content errors prevent silent truncation. Copies created by receiving apps are outside this cleanup.

## Research and judgment

The controlling [functional research/decisions](PLAN.md) and [UI placement/material brief](UI_FIT.md) were used. Relevant official references were refreshed: [PdfDocument](https://developer.android.com/reference/android/graphics/pdf/PdfDocument), [measured text layout](https://developer.android.com/reference/android/text/StaticLayout.Builder), [FileProvider setup](https://developer.android.com/training/secure-file-sharing/setup-sharing) and [Android sharing](https://developer.android.com/develop/ui/compose/sharing/send). No new document dependency or design library was introduced. The PDF skill's render-and-inspect workflow was applied to synthetic samples using Android's actual PdfRenderer.

Independent judgment: exporting a screenshot of the scroll screen would make pagination/text inconsistent and couple the document to device size. A separate PDF and PNG layout would create two sources of truth. The selected measured Canvas plan avoids both. Native readable text supplements the fixed-size page preview. The hook was executed and saved in `export-judgment-hook.json`; its fixed reminder is not evidence that the implementation is correct.

## Focused acceptance and limits

Fifteen unique affected methods pass across [initial results](export-first-results.json) and [final results](export-final-results.json): six document/cache/provider methods, five sharing UI methods and four existing statement-preview methods. Initial 13/14 passed; the sole failure assumed a long name must be rejected even though measured wrapping still fit. The corrected check accepts safe wrapping and rejects an actually excessive header. The final run is 11/11 affected document/sharing methods, including the new deterministic completed-export cancellation test. The four preview tests were already green and were not rerun after the isolated storage fix. No full suite ran.

Coverage includes exact row/closing reconciliation, all references on multi-page output, oversized statement/header rejection, wrapped Unicode names, PDF/PNG page count and sampled pixel agreement, aged/fresh/active cleanup, quota exhaustion, generation and return-boundary cancellation, missing files, selected read-only URI grants, denial of sibling/outside paths, changed facts after rendering, missing sharing handler, duplicate/busy controls and native chooser dismissal without choosing a target. The provider access check temporarily grants only a synthetic selected URI to the Android shell receiver, confirms the sibling stays inaccessible, then revokes it.

One-page and four-page synthetic PDFs were rendered by Android PdfRenderer and their first/last pages inspected against PNG output. Shop/customer identity, corrections, amount hierarchy, carried/final totals and page footers fit without clipping or overlap. Final format-choice and status captures were inspected in light/default and dark/200%-host text fixtures; title/navigation bounds stay fixed. These tests simulate the host's Compose font density; they do not certify every external receiver or device-wide font-setting combination. The first screenshot attempt caught a dialog-dismissal frame; final capture waits for animation/idle and shows the settled state. Binary samples and device captures stay local; reproducible drivers, result summaries and source/sample hashes are retained.

Only the disposable `com.saaf.milkshop.qa.tests` app/test package was installed/cleared on A06. Ordinary shop installations, financial data, production, schema/sync, customer contact and signed release delivery were outside this run. The ordinary phones still have the previously delivered 0.5.0/code8 release; this feature is currently in source and the isolated QA build.

Two compile-time authoring errors (PdfDocument is not Closeable; an untyped test empty set) were corrected before the first device run. The repair build command initially used the repository-relative driver path from the phase18 directory; that driver edit was rerun from the repository root. These retained local command/build failures are not production defects or successful checks.
