# Phase 5 piece 3: frozen execution boundary

16 October 2026; baseline `6ffe8a8`. This implements the third existing piece, using PLAN.md and UI_FIT.md. Stop after its affected acceptance; phase 6 is not included.

Verified storage: SecurityAuditEntryEntity supports arbitrary action/result/reason/details and optional actor snapshots. Its existing backup codec includes these entries; they are not the financial ledger or the live sync feed. Reuse a dedicated customer-communication action namespace, customer UID and minimal structured operation/channel/period/as-of/action metadata. Do not persist recipient overrides, message bodies, amounts, private flags or notes. Add bounded customer-specific DAO reads and idempotent exact-operation/action writes without changing the schema. History is local/possibly restored from backup, not cross-phone sending history or a suppression rule.

Reminder facts are one authorized Room read of configured shop, selected customer UID/name/saved phone, canonical current balance, business date and existing credit-status known-overdue facts. Never use the selected statement period's closing amount. Settled/advance customers have no payment-request draft. Include known overdue amount only when supported; label partial coverage explicitly and omit private risk judgments. Phone syntax accepts an explicit +country-code number with harmless formatting removed; no country inference, extensions or multiple recipients. Syntax does not prove WhatsApp registration or reachability.

Refresh official Android common messaging-intent documentation and WhatsApp click-to-chat help. Use ACTION_SENDTO/smsto plus sms_body for SMS, no SEND_SMS permission. Use an encoded wa.me link explicitly restricted to installed WhatsApp/WhatsApp Business; add only the two package-visibility declarations. If neither can handle it, show SMS as the deliberate fallback; do not silently open a browser and call that a composer. Launch success means Android accepted the request, not receipt/sending/delivery. No real composer with a real recipient is used in QA.

UI: the existing Customers host owns fixed header/footer. Add Reminder and Preparation history body panes under the statement task with the same crossfade and native information/selection controls. Reminder has recipient, read-only message/channel, explicit recipient confirmation, one primary Open action, reserved progress slot and persistent feedback. One-draft override is not auto-focused or saved to the customer. Back/navigation protects an edited override with the existing leave guard; keyboard has one body IME inset owner. Returning from the external app preserves the draft; facts are rechecked on each handoff. Changed identity/phone/balance/date/wording requires refreshed review and renewed confirmation, preserving override/channel. Statement sharing also records its observable prepare/chooser/failure actions through the same authorized boundary.

Independent judgment: existing audit storage is sufficient for observable local actions; a new synced reminder table would exceed the accepted scope. A WhatsApp web fallback would weaken the promised app-specific handoff, so failure stays visible. Direct SMS sending or inferred delivery would be both unnecessary and unverified. The judgment hook is a reminder only, not validation.

Pinned acceptance: reminder facts/permissions/current balance and known overdue; explicit international phone/URI/text encoding; idempotent minimal history/customer isolation/backup-codec preservation; light and dark/large-text body fit/stable chrome; changed balance or phone requires review; settled/advance and missing phone/app feedback; duplicate guard and denied launch; preserve draft on return/cancel and guarded override exit; statement-share history callbacks. Use only new tests and directly touched existing preview/share methods. One isolated A06 QA target; no ordinary install, backend mutation, schema, actual sending, full suite or new global design audit.

Sources: https://developer.android.com/guide/components/intents-common#Messaging and https://faq.whatsapp.com/5913398998672934 (official indexed click-to-chat text; direct help page body unavailable). Existing design references and implementation tokens remain UI_FIT.md's authority.
